Review target: commit 38e00893f9118557c3f0c93f6f1be4274efd8c8e.

These notes distinguish integration bugs from UI work the maintainer intends to own. The UI work below is a future plan, not a request for the PR contributor to implement it. No public PR comment or review has been posted.

## Integration findings

- Windows blocker, fixed locally: the patched local HF resolver returned mixed path separators. Normalizing those separators preserves configured symlink paths and makes the decoder's existing path consistency assertion pass. Verified with the actual local model path, all 17 ZONOS3 unit tests, and a successful live embedding-mode workflow after restarting ComfyUI.
- Explicit pause duration, fixed locally: ordinary chunk crossfades shortened explicit pause records during final assembly. With stub speech, a requested 0.25-second pause became approximately 0.05 seconds of silence. The shared combiner now concatenates boundaries beside aligned pause-only records, preserving the requested silence under every join mode without adding padding. Ordinary speech-to-speech boundaries retain their selected method. This also protects other processors that pass aligned pause records through the same combiner.
- Seed zero: the adapter sends the fixed native seed 0 and reuses its audio-cache entry, despite the unified nodes documenting zero as random generation.
- Language resolution: prioritize language codes over country aliases, retaining case-insensitive matching. UK/uk should resolve to Ukrainian; British English should use an unambiguous alias such as en-GB. Check engine mappings so en-GB reaches English where regional variants are unsupported. None of the 28 tracked example/test workflow JSON files uses UK values or tags. Existing engine language entries found for UK mean Ukrainian. OmniVoice's separate UK accent button inserts the phrase 'british accent' and does not use the shared resolver.
- Shared top_k maximum of 4096: accepted after tracing all affected engines and running CPU sampler/parser checks at 100, 101, 200, 1026 and 4096. Native filters clamp to vocabulary size or safely handle 4096. The increase also removes the old inline-tag mismatch with MOSS's 200 and Higgs v3's 1026 UI limits. IndexTTS's accelerated path already ignores top_k; this predates the PR.
- Long-form capability: the official Zyphra release article advertises a 32,768-position context and up to 10 minutes of continuous audio (https://huggingface.co/blog/Zyphra/zonos3-mini). This is a capability claim, not a tested best-quality chunk recommendation. The PR uses the suite character chunker, default 400 characters, and independent generation calls per chunk. Explicit max_new_frames can reach 9000 (approximately 10 minutes at 15 Hz); zero delegates to the reference implementation's remaining context budget and does not impose a separate 10-minute cap. Long-form inference and join quality remain unvalidated locally.
- Existing shared chunker bug, fixed locally: a short opening sentence followed by a 904-character sentence produced chunk lengths [16, 904] with max_chars=400. The oversized-sentence branch was bypassed when the preceding chunk was nonempty; oversized comma parts had the same issue. These predate the PR and affect execution paths using ImprovedChatterBoxChunker, not engines with separate chunkers. Oversized parts now split at word boundaries where possible, enforcing the limit without duplicating comma punctuation. Ordinary sentence packing is retained.
- Configurable chunk size, implemented locally: Unified TTS Text now allows 100–20,000 characters per chunk, retaining the 400-character default. The shared validator uses the same ceiling instead of silently clamping to 2,000. The tooltip explains character counts versus duration, engine limits and tag boundaries. This enables longer requests where supported; no ten-minute generation or quality claim has been validated.
- Steering socket mismatch: both option nodes return ZONOS3_STEERING, so Delivery & Mood can be connected to voice_design. The engine merges its effect strengths but silently ignores its timing and controls_cfg_scale fields, which it reads only from delivery. Reproduced identical engine configurations after changing steer_hold through the wrong socket. The user's live connection from delivery node 8 to engine node 7 was moved from voice_design to delivery using a verified graph patch. Add clear input-kind validation or distinct socket types so this mistake cannot silently discard settings. The FL-MCP queue command failed before submitting a verification run; corrected wiring and config propagation were verified, but no fresh audio result was claimed for this change.

## Current steering behavior

- Voice Characteristics controls modify the speaker embedding for the current generation. Delivery & Mood controls modify inference state while speech is generated. Both use upstream native controls; they are not free-form text instructions or post-processing effects.
- extra_controls is a list of named effects and numeric strengths, for example emotions.proud=3. It is not a timeline. Exact identifiers must exist in the bundled native controls. A duplicate identifier in this field currently overrides the corresponding slider.
- The separate timing fields define one shared envelope for eligible request-level delivery controls: start at full influence, hold initially, reduce over a transition, then retain a fraction of the original influence.
- Native defaults: 4 seconds at full influence, a 1-second reduction, then 35% remaining influence. The fraction measures model steering, not a percentage of perceived emotion.
- The current envelope cannot rise from low to high, define arbitrary keyframes, or schedule every effect independently. It restarts at each generation request/chunk/subtitle. Speaker-embedding controls stay constant; delivery.tempo and delivery.whisper are exempt from the reduction.
- The Mandarin accent helper combines a speaker-embedding adjustment with a hidden-state adjustment. Only its hidden-state component is eligible for the shared reduction envelope.
- Zero transition time makes the reduction immediate. Remaining strength 1 keeps full influence throughout; 0 removes the added eligible influence after the transition. A value of -1 in the existing node means to use native defaults.
- Upstream control_spans is a separate native feature for controlling text regions. This PR deliberately does not expose it. Do not conflate it with extra_controls or the shared envelope.

## Future maintainer-owned UI work

1. Use the rainbow naming convention: proposed display names are '🌈 ZONOS3-Mini Emotion & Delivery' and '🌈 ZONOS3-Mini Voice Characteristics'. Preserve serialized node identities and connections when changing display names.
2. Retain all emotion sliders and place a radar beneath them, as with IndexTTS. Reuse the shared widget through configurable emotion names, ranges and steps. Normalize only the plotted radius; retain each effect's native numeric values. Keep bipolar delivery/mood settings outside the emotion radar.
3. Retain Voice Characteristics sliders, grouped by identity, pitch, texture, recording character and accents. A radar is not suitable for this mixed set of controls.
4. Replace the raw extra_controls text field with discoverable controls for every supported native effect. Use grouped sliders where practical, or an 'Add effect' selector with a strength control, populated from actual bundled controls. Show readable names, limits or recommendations where officially supplied, and mode restrictions. Each effect should have one authoritative control, avoiding hidden overrides. This is already an optional advanced configuration node; reducing its slider count does not justify making users type fixed identifiers. Do not retain a raw identifier text field merely as an advanced fallback. A free-form instruction field would only be appropriate for a separately verified native capability that interprets arbitrary descriptions; this field does not provide that capability.
5. Give the envelope a distinct 'Effect strength over time' area, separate from the effect list. Use readable labels: 'Initial full-strength duration', 'Strength reduction duration' and 'Remaining strength (%)'. Present 'Use model defaults' explicitly. Keep control guidance separate as an advanced setting.
   The upstream reference implementation applies extra controls guidance only in embedding mode with an active hidden-state control. Make controls_cfg_scale mode-aware and explain that its default 1 disables only extra guidance, not the selected effects. Do not imply that raising it in reference mode strengthens effects.
6. Add a small live envelope preview with generated-speech seconds on X and relative steering influence on Y. Show the initial, reduction and remaining phases; state that it resets per generated segment and applies only to eligible controls. Reflect the supported native envelope, not arbitrary per-effect automation.
7. Add parameter switching for exposed native voice/delivery effects and envelope settings through the existing suite parameter system. Reuse node mappings, validation, cache identity and native mode restrictions. Treat the configuration node as the baseline, with per-segment overrides restored afterwards. Exact tag syntax is a later implementation decision. Precise within-segment changes would require separately scoped support for upstream control_spans.
8. Retain the existing shared chunker for ZONOS3: the official reference path used here does not supply its own text-chunk orchestration. The configurable Unified ceiling has now been raised to 20,000 characters, retaining the 400-character default. Character counts do not guarantee an audio duration; max_new_frames is a per-call generation cutoff and does not automatically move unread text into the next chunk. Do not label a character setting as an exact ten-minute duration.
9. Validate real multi-chunk assembly and unchunked long-form takes separately, including text coverage, prosody/identity continuity, steering-envelope resets, interruption and VRAM use. Review the native_long_form metadata against upstream capabilities and the shared-chunking integration policy. Do not present the generic 400-character default as an upstream model limit or claim the advertised 10-minute capability was validated by the short live smoke run.

## Parameter switching currently present in the PR

The ZONOS3 additions support seed, temperature, top_p, top_k, repetition_penalty, min_p, speaker_cfg_scale, loudness_bucket, fmax_bucket and speaking_rate_bucket, including their aliases.

The PR does not add parameter switching for the Voice Characteristics/Delivery sliders, arbitrary named controls, steer_hold, steer_onset_seconds, steer_ramp_seconds or controls_cfg_scale. Existing IndexTTS emotion tag aliases do not enable those controls for ZONOS3.
